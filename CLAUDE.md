# Ashfall-Modpack

Ashfall is a Fabric **Minecraft 26.3** zombie-survival modpack for singleplayer and 2–4 player co-op. Players
scavenge a ruined city generated by The Lost Cities, build a Bunker Core base, survive horde nights, recruit
survivors, and relight "Asheville" district by district up to the Black Start finale. The finale ends with a
Sever or Bind vote. The pack is published as `.mrpack` releases on GitHub: `walsodon-hash/Ashfall-Modpack` and its
wiki.

## Layout

- `modules/salvage`, `modules/director`, `modules/arms` are three mods in one Gradle build. Dependencies run
  arms → director → salvage, so salvage is the lowest.
  - **salvage:** city, loot, buildings, torch burnout, Matches and Lighter Fluid.
  - **director:** spawning, hordes, havens and Bunker Core, fortify and wear, infection, thirst, pets, senses, traps.
  - **arms:** blasters, blades, Flamethrower, survivors, traders, the grid and districts, story and finale.
- Data and balance live in JSON under `modules/*/src/main/resources/data/ashfall/ashfall/`.
- `pack/mods.json` pins every third-party mod as a Modrinth slug plus a version id.
- `pack/overrides/` holds the shipped configs and the optional "Ashfall Polished Arms" resource pack.
- `docs/player-guide.md` is the source of player-facing facts. `docs/wiki/ashfall-wiki.html` is the field manual,
  published at https://claude.ai/artifact/JpfqXRU3ZMTcpQDNZYGFHJ.
- `docs/versions.md` maps every release. `docs/releasing.md` is the release checklist. `CREDITS.md` lists licences.
- `tools/` holds the generators:
  - `build_mrpack.py` builds the pack;
  - `gh_wiki.py` and `render_wiki_figs.py` build the GitHub wiki and its diagrams;
  - `wiki_recipes.py` builds the recipe tables;
  - `gen_polished_arms.py` builds the Polished Arms skins;
  - `tools/models` and `tools/textures` hold procedural art (stdlib Python, run with `python3 -I`; the system Python
    is 3.8).

## Build and test

- Build with `./gradlew build`.
- Gametests run with `./gradlew :salvage:runGameTest`, `:director:runGameTest` and `:arms:runGameTest`. Run gradle
  tasks one at a time, never two at once. Write output to a log file, never pipe it into `head`.
- Build the pack with `python3 -I tools/build_mrpack.py`, which writes `dist/Ashfall-<version>.mrpack`.
- Static mutable collections must be cleared on `SERVER_STOPPED` (`StaticStateAuditTest` enforces it).
- In tests that flip a shared game rule, restore it in the same synchronous block.
- Wait for light updates in tests instead of reading them on the next tick.

## Versioning and releases

- Versions are MAJOR.MEDIUM.MINOR, set in `gradle.properties`.
  - Medium: new features or a world-generation change.
  - Minor: fixes and balance tweaks, even large rebalances.
- Every release gets a `docs/versions.md` row, the wiki's "Written for Ashfall X" line, a README entry in the release
  repo and an updated field manual. Follow `docs/releasing.md`.
- The release clones live in `.cache/release/`. Commit as `walsodon-hash` (global git identity) and push with
  `git -c http.postBuffer=524288000 push`.
- **Commit or push only when the user asks.**

## Rules from the user

- Original names and art only: no Star Wars terms, no copied PSWG art.
- Every mod in the pack must be clearly licensed for modpack use. Credit each one in the README.
- Never run `spark health` or any spark upload command.
- Don't modify the user's Prism instances or worlds; reading their logs is fine. Don't run untrusted binaries. Use
  `"${VAR:?}"` with `rm`. Don't use broad process-kill patterns.
- Keep the docs and field manual in step with gameplay changes. Report honestly what wasn't checked in game.
- Pace token use. Give the user a simple plan first for bigger work, and ask about real design choices.
